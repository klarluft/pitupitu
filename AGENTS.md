# pitupitu (box agent)

The open-source agent that runs on the user's machine and links their coding agents, running in herdr, to pitupitu cloud over one outbound WebSocket. Read `README.md` for what it does, `docs/box-link.md` for the protocol and `docs/sessions.md` for what every state and error means.

- This repo is the box agent only: its code, the box link protocol docs, `README.md`, `CONTRIBUTING.md` and the skill. Product plans, ideas, notes and to-do lists do not live here, not even as a draft. A commit message or pull request describes its own change and nothing more: no links to other repositories' work and no quoted conversations.
- Keep it small: it serves the box link calls through the herdr the person keeps open, reports its inventory and the home folder's skills, sends the agents' session history (and a session's last reply when asked) unless the person switched it off, updates itself and herdr when asked, and installs itself as a user service. Conversation, voice and everything else is the cloud's.
- `crates/herdr` is the only crate that runs `herdr` (`herdr --skill`, `herdr api schema` for exact payloads): `cli.rs` the `AgentHost` over herdr's CLI, `admin.rs` herdr itself (status, updating, integrations), `detect.rs` what a screen shows. Key "a turn finished" on `completion_seq`, never on the `done` status.
- `crates/pitupitu`: `calls.rs` (call → `AgentHost` method, scratch tabs), `link.rs` (socket, hello, notes, the `update` call, liveness, reconnect), `herdr_box.rs` (herdr on this box: the inventory's `herdr`, the install setup offers, updating it), `mac_folders.rs` (setup has the service open the folders macOS guards, where the box reads projects, so the Mac asks while someone is there), `inventory.rs`, `logs.rs` (where each agent keeps its session logs, listed without being read; OpenCode's and Kilo Code's databases, read-only, their `session`, `message` and `part` tables only; Antigravity's summaries, read-only, a conversation's folder and title only), `history.rs` (the session reader, with the other harnesses' parsers in `history/harnesses.rs`, on unless switched off, and git facts: what it may read and send is in `docs/box-link.md`, "History"; keep its never-sent list), `settings.rs`, `list.rs` (the person's list, reminders and schedules, over the cloud's REST API), `skill.rs`, `home.rs`, `device.rs` (sign-in), `config.rs`, `service.rs`, `update.rs` (the box agent's own update and the release checks: shown and asked, never silent; sessions untouched). `lib.rs` exposes these to the tests under `tests/`.
- herdr runs the person's own, unmodified agent CLIs; the box never reads their credentials or adds permission flags. Keep it that way.
- herdr's server is the person's: they open `herdr` in a terminal of their own login session, and the box only connects to it. The box never starts, restarts or stops a server (on macOS a server started by the service would have its panes' privacy requests, the microphone included, charged to pitupitu); when none answers it says so, with the fix. It never installs herdr without asking, and never updates itself or herdr unasked.
- The cloud may only do what a named call allows; no shell, no arbitrary herdr command.
- The skill (`skill/SKILL.md`) is the agents' manual for the CLI: a CLI change updates it in the same change. The tests in `crates/pitupitu/src/skill_drift.rs` fail when a command it shows does not parse or a command is missing from it.
- Logs: metadata only, never prompts, agent output or file contents.
- Live herdr tests: a throwaway named session (`herdr --session`), its server started by the test itself (never by shipped code) and then stopped and deleted; never the person's own session. Inside it, create your own workspace or tab and close it.
- macOS releases are signed with the Developer ID (`packaging/macos/package.sh`, as `chat.pitupitu.box`), as a plain binary and as `pitupitu.app` for Homebrew: macOS keeps privacy answers across updates only for signed builds, and across Homebrew's per-version folders only for the app. Never ship an ad-hoc signed macOS release.
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test` clean before committing. Commits are signed off (DCO).

`CLAUDE.md` only imports this file.
